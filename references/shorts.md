# Короткие: Shorts / Reels / TikTok

Конвейер: `scripts/shorts/build.py` (спеки `<ролик>/stage12_shorts/specs/<id>.json`, формат ниже), цвет камеры `scripts/shorts/cam_lut.py` → `cam.cube`. Видео — из ИСХОДНИКОВ (не из рендера мастера), время — через `stage3/timeline_map.json` + `transcript_timeline.json`. Начинать после экспорта мастера: `config.json` → `master_render` (по нему калибруется `cam.cube`: `python -X utf8 scripts/shorts/cam_lut.py --config config.json` → `<work_dir>/stage12_shorts/cam.cube`, пересчитывать на каждый ролик). Если мастер доделан в копии проекта — `master_maps`: папка с `timeline_map.json` + `transcript_timeline.json` той копии (по ней выкидываются слова, вырезанные в мастере, и ищутся кадры для калибровки); по умолчанию `<work_dir>/stage3`.
Все пути — от `work_dir`: спеки `stage12_shorts/specs/`, работа `stage12_shorts/work/<id>/`, результат `stage12_shorts/out/`.
Одна спека → три сборки: без флага (Shorts), `--reels`, `--tiktok`. Правила цвета, зумов, звука — общие.

## Три платформы
| Платформа | Длина | Концовка / CTA |
|---|---|---|
| YouTube Shorts | ≤ 60 с (обычно 26–54 + 2.5 с) | «ПОЛНЫЙ ГАЙД · N МИНУТ / В ПРОФИЛЕ ↑», 2.5 с — `end` в спеке |
| Instagram Reels | ≤ 30 с включая карточку | «Напиши «СЛОВО» в комментариях — пришлю полный урок», 4 с, кодовое слово в спеке (reels.md) |
| TikTok | ≤ 15 с тизер | Скрин превью YouTube + «Полное видео на YouTube: <канал>», 2.5 с (tiktok.md) |

На вопрос про одну платформу — отвечать только про неё.

## 1. Цвет камеры (iPhone HLG HDR)

Камера iPhone `*.MOV` — HEVC 10 бит, HLG (arib-std-b67), BT.2020. CapCut конвертирует сам, ffmpeg — нет.

| Попытка | Что сделал | Результат | Почему |
|---|---|---|---|
| 1 | Без конверсии, просто yuv420p | Блёкло, «засвечено» | HDR-сигнал показан как SDR |
| 2 | zscale npl=100 + tonemap=hable | Пересвет | Пик HLG 1000 нит приравнял к 100 → всё светлое (стена, лицо) упёрлось в белый |
| 3 | Резать прямо из рендера мастера | Отвергнуто | В рендере камера уже кадрирована/зазумлена: лицо обрезано, свои зумы мастера мешают оценить зумы шортса |
| 4 | Свободный 3D LUT / матрица, подогнанные под рендер | **Розовые губы** | В кадре почти всё серое/чёрное → насыщенные цвета не определены, подгонка перегнула красный (усиление R ×2.4). Проверял по средней ошибке всего кадра — стена совпала, губы проскочили |
| 5 ✅ | Честная конверсия zscale `npl=1000` (BT.2020→BT.709, без тонмаппинга) + по рендеру подгоняются ТОЛЬКО кривые по каналам (яркость/баланс) и ОДИН общий множитель насыщенности (×1.18) | Совпадает с CapCut | Жёсткая модель не может покрасить отдельный оттенок |
| 5+ | По просьбе: губы чуть менее красные — снижение насыщенности на 30% только у насыщенного оттенка ~350° (кожа ~7–12° не задета) | ок | `lips()` в `scripts/shorts/cam_lut.py`, `LIPS_DESAT` |

**Выводы**
- Не подбирать тонмаппинг на глаз. Эталон — кадр рендера CapCut того же момента; калибровать по нему.
- Подгоняемая модель должна быть жёсткой (кривые + одна насыщенность), никаких свободных LUT/матриц на «серой» сцене.
- Проверять по **крупному плану лица** (губы, щёки) рядом с рендером, а не по средней ошибке кадра.
- Цепочка декода в сборке должна совпадать с калибровкой байт в байт (`cam_lut.SRC_VF` + `lut3d`).
- `cam_lut.py` берёт моменты камеры во весь кадр (строки F `layout/layout.json`, камера на главной дорожке), потом любые куски камеры; кадр, не совместившийся с рендером (< 200 точек ORB — кружок, графика), отбрасывается. Нужно ≥ 6 обучающих кадров, иначе ошибка → `--times T1 T2 …` (моменты таймлайна мастера с камерой во весь кадр, ~17 штук: каждый 5-й — тестовый). Проверка — `stage12_shorts/work/lut_check.jpg`.

### Профиль ref (look монтажёра, 2026-10-25)
По умолчанию `config.json` → `"color_profile": "ref"`: камера декодируется той же цепочкой `SRC_VF` + `lut3d=assets/ref_joint.cube` (LUT 33³, подогнан по 98 парам кадров «сырой MOV ↔ рендер монтажёра» двух роликов, hold-out каждая 5-я пара; отчёт `refs/train/color/REPORT.md` в рабочей папке ролика). `"master"` — прежнее поведение: `cam_lut.py` калибрует `<work_dir>/stage12_shorts/cam.cube` по `master_render`.
- Что показал эталон: look монтажёра ≈ **честный декод HLG→709 без тонмаппинга** + света прижаты (белое 1.0 → 0.94, B в светах −5/255 — теплее), средние +1…2/255, насыщенность ×0.985, тени B +2. Ошибка сырого декода 5–7/255, с LUT 4–7/255 на обоих роликах (LUT одного ролика на другой — хуже сырого, поэтому только joint).
- **«Temp −18, Saturation 10» — противоположно эталону**: эталон тёплый в средних (R−G +18…+24, B−G −14…−18), как и сырой декод; Temp −18 уводил на −10 по R−G и +15…+18 по B−G. В CapCut для длинного ролика стартовая точка: Temp 0, Tint 0, Exposure +2…+3, Contrast +4, Highlights −15…−20, Shadows 0, Saturation −5 (шкала CapCut не документирована — сверять рядом с кадром эталона).
- Остаток, который LUT не покрывает: поклиповая экспозиция/баланс монтажёра (±0.3 EV, до 14–18/255 на хуке A) и зелёный LED микрофона (SATMAX 104–115 у нас против 72–98). Делать поклиповый exposure-match, если кадры заметно разные.
- Спекуляры HDR (окна, лампы) в парах не встречались — поведение LUT выше 0.8 не проверено.

## 2. Зумы

Правила пользователя:
- Зум **только когда камера на весь экран** (в стеке «кружок сверху + скринкаст снизу» — нет).
- Камера **всегда** медленно приближается или отдаляется.
- На акцентах — мгновенный или быстрый плавный (0.5–0.75 с) наезд, **приходит на ударный слог** (ищу пик громкости внутри слова).
- Масштаб **строго от центра кадра**, как Scale в CapCut.
- **Перед склейкой зум не делать** (дрыганье): если от ударного слога до склейки < 1.2 с — акцент пропускается.

Ошибки:
- Зумил к точке у лица + кадр упирался в край → лицо съезжало, «двойной зум».
- Центр кропа искал по лицу на каждом куске → кадр прыгал на склейках. Теперь один центр на весь шортс (медиана x лица).
- Акценты ставил на любое ключевое слово субтитров (любое слово из субтитров) → зум без смысла. Теперь: цифры + явный `spec["accents"]`.
- Маленькая смена уровня зума на склейке (~5%) выглядит как дёрг, а не приём. Фон теперь — непрерывная волна 1.00↔1.10 (период 10 с), склейки её не сбрасывают.

## 3. Текст и раскладка
- **Текст никогда не на лице.** Хук ставился всегда вверху (y=380) → в шортсе, который начинается с камеры во весь кадр, лёг на лицо. Теперь `HOOK_TOP` по раскладке: стек → на скринкаст, камера во весь кадр → нижняя треть.
- Не форсировать «камеру во весь кадр» (`layout: full`) для боковой камеры (той, что в ролике кружком): на весь экран видно затылок и спину.

- Карточка не должна появляться, пока на экране хук (пример: перекрытие на 2.5 с). В сборке: карточки и пункты не раньше `hook.dur + 0.35` с.
- Скачок цвета камеры внутри шортса может быть в самом исходнике (пример: iPhone сдвинул баланс белого от белого экрана с таблицей — в рендере CapCut так же). Сначала сравнить с рендером, потом чинить.

## 4. Смысл и резка
- Шортс не должен обрывать мысль там, где её обрезал монтаж длинного ролика (пример: «в 40 раз больше просмотров» без «чем обычно…»). Проверять концы фраз по исходной транскрипции `transcript/transcript.json`; инструменты спеки: `extend_src` (дотянуть кусок из исходника), `force_tl` (вернуть слово).
- Слова, вырезанные в мастере, выкидываются (`rmap.find`), но сверка — **по времени в исходнике**, не по тексту: распознавание в мастере пишет иначе (пример: «Анти-топ» / «Анти -топ») → иначе остаётся обрывок слова.
- После автоматического выкидывания слов проверить глазами: служебные (пример: «Окей», «Вот») — пусть уходят; несущие смысл (пример: «Как…», «Сможем ли…») — вернуть.

## 5. Звук
Жалоба «как будто шумы два раза убрали». Причина:
- Исходник (звук скринкаста) **уже без шума**: шумодав стоял при записи, паузы −84 дБ. Я сверху гнал `afftdn` → двойное шумоподавление.
- Шумодав съел верха: 2–4 кГц после обработки на ~5 дБ ниже исходника (несмотря на мой +3 дБ shelf), на ~9 дБ глуше, чем голос в рендере CapCut (Voice Crisper) → глухо.
- Ускорение ×1.15 через `atempo` → фазовость. Заменил на `rubberband` (transients=crisp, pitchq=quality).
- Сейчас: без шумодава, EQ `VOICE_FX` (highshelf +5 дБ от 2.5 кГц, +1.5 на 5 кГц, −1.5 на 250 Гц) + компрессор. Спектр совпал с рендером CapCut (2–4k −12.2 vs −12.9 дБ отн. 200–1k).
- `rubberband` с `transients=crisp:window=short:phase=laminar` → пользователь: «ещё хуже, роботизированный». Не ставить настройки для перкуссии на голос. Дальше — A/B-файлы на слух (`ab/`), выбирает пользователь.
- **Вывод:** перед обработкой звука измерить исходник (уровень пауз = был ли шумодав) и сравнить спектр с эталоном (рендер мастера). Не накладывать шумодав вслепую.

### Итог по звуку (выбор пользователя на A/B)
- Голос берётся из **исходника** скринкаста, эффекты заново ffmpeg-цепочкой `VOICE_FX`, подогнанной по спектру под рендер CapCut с Voice Crisper. Звук камеры не используется.
- **Без ускорения** (`SPEED = 1.0`). Любое растяжение голоса портит звук: atempo — «странно», rubberband — «роботизированно». Паузы и паразиты и так вырезаны; шортсы вышли 26–54 с + 2.5 с концовка (всё < 60 с). `atempo` остаётся только для кусков, ускоренных в самом проекте (`tempo_af`).
- **Без шумодава** (`afftdn` не ставить: исходник уже чистый с записи, двойной шумодав глушит верха). Перед обработкой измерить уровень пауз исходника.
- Цепочка голоса `VOICE_FX`: `highpass 80 Гц → EQ 250 Гц −1.5 дБ → highshelf +5 дБ от 2.5 кГц → EQ 5 кГц +1.5 дБ → компрессор (−20 дБ, 2.5:1, 5/120 мс, makeup +2)`.
- Громкость финала: гейн + лимитер (на 4× передискретизации, TP после AAC ≈ лимит), замер после AAC, до 6 проходов, пока не −14 ±0.5 LUFS и TP ≤ −1.1. Шаг гейна — по наклону двух последних проходов (за лимитером 1 дБ гейна даёт меньше 1 LU на пиковом голосе; шаг «на всю ошибку» недобирал: пример −15.6 / −14.8 LUFS). Берётся лучший проход. Не в норме → сборка завершается с ошибкой (exit 1), файл остаётся в `work/<id>/final*.mp4`, в `out/` не попадает.
- Микс: голос −19 LUFS, музыка = голос −13 LU, вуш пик −22 dBFS, финал гейн + лимитер → ≈ −14 LUFS / TP ≤ −1.

### Профиль ref (эталон монтажёра, 2026-10-25)
Пункты выше — профиль `legacy` (голос подогнан под рендер CapCut с Voice Crisper, финал −14). По умолчанию теперь профиль **`ref`**: звук как в шортсах монтажёра (`refs/train/voice/REPORT.md` в рабочей папке ролика — замеры двух эталонов и подгонка цепочки). Переключение — `config.json` → `"audio_profile": "ref" | "legacy"`; `legacy` = ровно прежнее поведение.
- Что показал эталон: голос монтажёра = **сырой тёмный микрофон без обработки** (4–6k −21, 6–8k −22, 8–12k −28 dB отн. 500–1 кГц; −17…−18 LUFS, TP −1, крест 18–19, LRA 1.6–4), без EQ/шумодава/Crisper; ускорение ×1.10 с сохранением высоты (у нас не применяется, см. выше); музыка −15…−17 LU под голосом, начинается сразу после хука.
- Шортс берёт голос из **звука скринкаста** — спектр другой (ярче, менее сжат), поэтому фиксированная цепочка не ложится на эталон. Вместо неё **подгонка по спектру** (`scripts/shorts/voice_ref.py` → `match_fx(voice_raw.wav)`): замер полос источника (речевые кадры, Welch 4096, dB отн. 500–1000 Гц, как в отчёте), на каждую полосу 80–160 … 8–12k один `equalizer` (t=o, центр — геометрическая середина полосы, гейн = цель − источник, не более ±8 dB), второй проход по остатку; дальше фиксированные ступени: HPF 70, лёгкий де-эссер, компрессор 1.8:1 (крест не трогает), dual mono. Цель `REF_BANDS` = среднее ref A / ref B: 80–160 +1.5, 160–250 +6.4, 250–500 +6.8, 1–2k −9.5, 2–4k −14.0, 4–6k −21.3, 6–8k −22.4, 8–12k −27.6. Допуск ±2 dB в 80 Гц – 8 кГц; 40–80 не фитится (там бас музыки эталона), только HPF.
- Числа профиля: голос −17.5 LUFS до микса, музыка = голос **−16 LU**, старт музыки = конец хука (`"music_in"` в спеке, секунды от начала шортса; fade-in 0.3 с), финал **−17.5 ±0.5 LUFS, TP ≤ −1.0** (лимитер почти не работает, крест остаётся ~19 против 12–13 при −14). Вуш как раньше (пик −22 dBFS до финального гейна).
- В логе сборки: `профиль звука: …` и `EQ по спектру (dB): …` (гейны по полосам, число проходов, в допуске или нет). Подгонка — `work/<id>/voice_match.json` (спектр до / после / цель / гейны), в `report.json` — `profile`, `voice_match`, `music_in`.
- Проверка на реальном голосе скринкаста (`refs/train/voice/screencast_check/`): все полосы 80 Гц – 8 кГц в пределах 1 dB от цели, −17.5 LUFS, TP −1.1, крест 19.2 (эталон 18.6); A/B — `ab_screencast_ours_8s.wav` рядом с `ab/A_mid_1_ref.wav`.
- Автономно (файл микрофона, не шортс): `python -X utf8 scripts/shorts/voice_ref.py in.m4a out.wav` (подгонка по спектру) или `--mic` (фиксированная цепочка `VOICE_FX_REF` из отчёта: микрофон уже эталонный, только 7 кГц −2 dB).

## 6. Процесс
- Собирать **один** шортс, ждать «ок» пользователя, только потом пачку. Я 4 раза запускал и убивал пачку из-за правок после запуска; пользователь спросил, что это за сборки.
- Фоновые циклы-ожидания (`until …; do sleep; done`) после убийства сборки надо останавливать, иначе висят вечно (накопилось 4 шелла).
- После ок на первом — пачка параллельно субагентами (2–3 группы, каждая собирает свою последовательно и проверяет контактный лист).
- Заголовки для Shorts — по правилу YouTube-заголовков (rules.md).
- Менять файл, который читает идущая сборка (cam.cube), нельзя — получится смесь старого и нового.
- `--no-render` нельзя после изменения плана: возьмётся старая графика со старыми таймингами субтитров.
- На Windows bash-heredoc с длинным Python ломается — патчи писать файлом.
- opencv 5.x без `CascadeClassifier` — ставить `opencv-python<5`.

## 7. Склейка, кроп, проверка
- **Баг склейки (пример: «обрезана середина»)**: при чистке границ кусков короче 2 кадров выкидывалась граница сегмента мастера → следующий кусок брал источник по предыдущему сегменту (смещение ~1 с) и затем прыгал. Границу сегмента выкидывать нельзя — это смена источника; теперь двигается край интервала. Проверка после сборки: у соседних кусков одного файла `sc.start[i]+src_dur[i] == sc.start[i+1]`.
- Кашель/вдох перед первым словом диапазона: `"lead": 0.5` в range + сдвинуть `tl[0]` на начало чистого звука; слово, начавшееся раньше, в субтитры попадает.
- Карточка/списки не должны лежать там, куда показываю на скринкасте. Шапка профиля — вверху скринкаста → карточка `top: 1430` (низ).
- Телефон: кроп скринкаста 1300 px (0.83×) не читается. Теперь 900–1100 px (1.0–1.2×) по смыслу момента (пример: шапка страницы, сетка, график). Для широких графиков — 1200, иначе режет края.
- `check/*.png` могут не обновиться после сборки — сверять кадр из `out/<id>.mp4`, а не из check.

## 8. Скринкаст: зум за курсором
Пользователь: «я говорю, что у нас разделение по дням и часам, и указываю курсором на блок — на телефоне ничего не будет видно, очевидно, нужно приблизить. Нельзя делать графику поверх того, о чём я говорю».
Правило:
- **Скринкаст двигается (курсор, скролл, ховер) = я что-то показываю.** Зумить в это место (окно ~900 px из 2560) и/или подсвечивать. Графику туда не класть.
- **Скринкаст статичен** → можно вообще закрыть его сплошным блоком #0A0A0A/белым и ставить графику на него.
- Один статичный кроп на весь range (как было, 1200 px) — на телефоне нечитаемо и не следует за речью.
- Как делать: вытащить кадры скринкаста по диапазону (сетка каждые 1.5–3 с), найти, куда ведёт курсор/тултип, сопоставить со словами → `ranges[].keys` в спеке (`{"tl", "zoom":[x,y,w,h]}`), переход 0.6 с smoothstep (`sc_filter`/`key_expr` в build.py: покадровый `scale … eval=frame` + `crop` с выражениями; `crop` с переменными w/h ffmpeg не умеет).
- Ключи разносить больше, чем ease (0.6 с); первый ключ range — состояние на входе (жёсткая склейка, без перехода).

- Пример: зум за курсором вместо центра. Окно 900 px: y+h не должно доходить до 1440 — внизу панель задач Windows (y ≤ ~480).

### Метод разметки «зум за курсором» (одобрен пользователем)
1. Диапазон range → по `stage3/timeline_map.json` (track 0) перевести tl в время исходника скринкаста: `src = source_in_us/1e6 + (tl − timeline_in_us/1e6)`.
2. Вытащить кадры каждые 1.5 с (`ffmpeg -ss … -frames:v 1 -vf scale=1280:-1`, без drawtext — fontconfig ломается), склеить в сетку PIL с подписями tl. Смотреть сетку целиком: видно, где меняется экран (прокрутка, другой блок).
3. Слова range из `stage3/transcript_timeline.json` рядом: по сетке + словам найти моменты «я показываю на X».
4. На спорные моменты кадры в полном 2560, кроп контентной колонки (x 250–1650) с сеткой 100 px → снять координаты курсора/блока. Пересчёт из показанного превью: x = 250 + disp·k, где k = ширина кропа / ширина панели.
5. Ключи в спеку `ranges[].keys`: первый = состояние на входе; дальше ключ за 0.2–0.5 с до слова, окно 900×900, разнос ключей ≥ 1 с. Окно должно вмещать подписи строк, а не только то, куда ткнул курсор (иначе строка без названия нечитаема).
6. Собрать, вытащить кадры результата на ключевых словах (через `plan.json`: `out = s0 + (tl − tl0)`), сетка, проверить: подписи не обрезаны, низ окна не достаёт панели задач (y+h < ~1380).
7. Старый рендер — `work/<id>/final_prev_*.mp4` для сравнения.

## Спека (specs/<id>.json)
Полный образец — `assets/examples/specs/example.json`.

```json
{
 "id": "01", "slug": "slug", "title": "…",
 "ranges": [ {"tl": [100.0, 140.0], "zoom": [560, 90, 1300, 1300]}, … ],
 "hook": {"kicker": "Тема", "lines": ["строка 1", "строка — <span class=\"or\">акцент</span>"], "dur": 2.4},
 "cards": [ {"tl_in": 420.0, "tl_out": 430.0, "title": "…", "items": [{"text": "…", "at": 421.0}, …], "top": 920} ],
 "keywords": ["подстрока"],
 "end": {"kicker": "ПОЛНЫЙ ГАЙД · N МИНУТ", "line": "В ПРОФИЛЕ ↑"},
 "cap_top": 760,
 "fix": {"ошибка": "исправление"},
 "cam_cx": {"<файл камеры>.MOV": 1150},
 "fillers": true
}
```
- Также: `extend_src` [{after_tl, to (сек. исходника)}] — дотянуть кусок из исходника; `force_tl` [начала слов stage3] — вернуть слово; `accents` — явные акценты зума; `lead` в range — сдвиг начала после кашля/вдоха.
- `ranges[].tl` — таймлайн stage3 (stage3/transcript_timeline.txt / .json), секунды. Берутся слова, чьи start/end внутри диапазона; паузы > 0.3 с режутся; «так,/значит,/короче,/ну,/вот,» в начале фразы выкидываются.
- `zoom` — [x, y, w, h] в px скринкаста 2560×1440, нижняя половина кадра 1080×1080, т.е. квадрат (w=h, подгоняется автоматически). По умолчанию [560, 90, 1300, 1300] (центр контента без панели браузера и таскбара).
- `keys` в range — анимированный зум скринкаста за курсором: `[{"tl": 105.2, "zoom": [706,150,900,900], "ease": 0.6}, …]`. Первый ключ — состояние на начало range, дальше плавный переход за `ease` (по умолчанию 0.6 с). Где я показываю курсором — окно ~900 px; где скринкаст статичен — обзор 1300. См. §8 выше.
- `layout: "full"` в range — принудительно камера во весь кадр (если есть камера). Без него: камера во весь кадр берётся автоматически там, где в проекте камера во весь кадр (по timeline_map); остальное — стек камера сверху (1080×840) + скринкаст снизу (1080×1080).
- `hook` — плашки в верхней части, 0 → dur. Оранжевый — `<span class="or">…</span>`. ≤ 3 строки, ≤ 16 символов в строке.
- `cards` — список-карточка поверх скринкаста (top 920…): title (плашка), items (номер + плашка), появляются по `at` (таймлайн) или через 0.25 с друг за другом. Можно `html` со своей разметкой (классы из shorts.css: .plate .num .sq .arrow .hrow), `{in}`/`{out}` подставляются временем шортса.
- `keywords` — подстроки (нижний регистр), по которым слово в субтитре красится в оранжевый; цифры/×/% красятся всегда.
- Сборка: `python -X utf8 scripts/shorts/build.py <id> --config config.json`; `--plan` — только план (work/<id>/plan.json: куски, субтитры); `--no-render` — без перерендера графики. Длина с концовкой больше лимита платформы (60 / 30 / 15 с) → ошибка сразу после плана, рендер не идёт.
- Слова таймлайна для выбора границ: `python -X utf8 -c "import sys; sys.path.insert(0, 'scripts/shorts'); import build; c = build.load('config.json'); [print(w['word'], w['start'], w['end']) for w in c.words if A <= w['start'] <= B]"`.
- Звук: профиль `config.json` → `audio_profile` (`ref` по умолчанию / `legacy`, §5). `"music_in"` — старт музыки, с от начала шортса (профиль ref; по умолчанию конец хука). Музыка — `"music"` в спеке (имя файла в `music_dir` или абсолютный путь), иначе первый файл `music_dir`; вуш — `"whoosh"` в спеке (путь внутри `sfx_dir`), иначе первый файл в `sfx_dir` (с подпапками) с «вуш» / «whoosh» / «swoosh» в имени. Такого файла нет → ошибка (задать `"whoosh"`). `music_dir` / `sfx_dir` не заданы → сборка предупреждает и сводит без музыки / без вуша.
- Раскладка: камера во весь кадр — где камера на главной дорожке или строка F в `layout/layout.json`; камера на других дорожках — кружок (стек); без камеры — скринкаст на весь экран (`scfull`).
- Результат: out/<id>_<slug>.mp4, кадры для проверки work/<id>/check/*.png (из этой сборки), отчёт по громкости work/<id>/report.json (`report_reels.json` / `report_tiktok.json`), графика `gfx.mov` (`gfx_reels.mov` / `gfx_tiktok.mov`).
- `fix` — замены слов в субтитрах (слово без знаков препинания → замена). `cam_cx` — центр кропа камеры по x (px исходника): `{"<файл камеры>": x}` для кусков-стека или одно число на весь шортс; по умолчанию — медиана x лица (по кускам «камера во весь кадр», иначе по стеку).

### Схема (type: scheme)
Полноэкранная вставка «кто есть кто» / «схема» по образцу референса (`refs`-разбор: узлы с иконкой, подписи по словам, числа жёлтым, пунктирные дуги, переезд камеры по бесконечной сетке). Генератор — `scripts/shorts/scheme.py`; в спеке — карточка `cards[]` с `"type": "scheme"`. Образец — `assets/examples/specs/scheme_example.json`, готовая страница — `assets/examples/html/scheme_whoiswho.html` (открыть в браузере, `seek(t)` от начала схемы).

- **Камера скрыта.** Панель непрозрачная на весь кадр 1080×1920 (чёрный фон + тёплый градиент снизу) — в `gfx.mov` она закрывает камеру и скринкаст целиком. Субтитры внутри интервала схемы не ставятся (субтитр, начатый раньше, обрезается на её старте); хук поверх схемы запрещён — схема не раньше `hook.dur + 0.35` с, иначе ошибка. Зумы камеры под схемой не важны. Вход/выход — жёсткая склейка.
- **Времена** (`start`, `end`, `at`, `pan_at`, слова) — секунды таймлайна stage3, как у остальных карточек; в шортс переводятся той же картой, что субтитры (куски, вырезанные паузы). Проверка при плане: каждое слово/узел/переезд внутри `[start, end]` и внутри оставленного куска — иначе ошибка с именем слова (слово в вырезанной паузе → сдвинуть время на звучащее слово).
- **Ритм**: одно появление на одно произнесённое слово (время слова из транскрипта, ±1 кадр); новый субъект речи → новый узел + переезд камеры; число в речи → отдельная жёлтая строка крупнее (`number`), расшифровка — строкой ниже (`line3`); фраза на экране ≤ 1 с, потом cut и новая (`out`, по умолчанию — начало следующей фразы узла). В строке ≤ 4 слов, в блоке ≤ 3 строк.
- **Палитра** (`style`, значения по умолчанию): `accent` #F8DE03 (числа, свечение 18 px), `bg` #000000, `bottom` #60260A (радиальный градиент от нижнего центра через `mid` #371606), сетка `grid` 108 px, белая 22 %; подписи #FBFBFB с тенью, Unbounded 700 кегль 50 / число 800 кегль 84, строчные; дуги #E1E1E1 пунктир 14/17; свечение иконок белое. Для бренда «Монолит» задать `"accent": "#D46A40"`. Логотипы третьих лиц — в их фирменных цветах (единственное исключение из «других цветов нет»).
- **Иконки** (`nodes[].icon`): встроенная `avatar` (серый аватар) или путь к png/svg (от папки ролика `work_dir` или абсолютный) — настоящие логотипы даёт пользователь. `ayugram` / `funpay` — встроенные заглушки образца, в реальный шортс не ставить. `shape`: `circle` (Ø404, картинка кропом в круг) | `plate` (белая плашка 572×244 со скруглением 36, картинка вписана); по умолчанию круг.
- **Геометрия**: активный узел всегда в точке (540, 870); узлы в мировых координатах, `offset` — сдвиг от предыдущего узла (по умолчанию [830, 900]; референс чередует (+830, +900) и (−440, +960) — зигзаг вниз). Подпись — под иконкой по центру, не ниже y≈1300.
- **Анимация**: узел — scale 0→1 с перелётом 8 % за 0.35 с (`at`); слово — из y+28 px за 0.12 с; переезд — ease-in-out 0.45 с (`pan`, старт `pan_at`, по умолчанию `at − pan`); дуга от предыдущего узла рисуется через 0.1 с после старта переезда за 0.35 с.
- **SFX** (через микс `build_render.mix`): тик на каждый pop узла — файл `"tick"` в спеке или первый в `sfx_dir` с «tick» / «клик» / «click» в имени (нет → строка в выводе, без тика); короткий вуш на каждый переезд — тот же вуш, что у хука; слова — без SFX. Уровень — пик −22 dBFS, как у вуша.
- Проверка без сборки: `python -X utf8 scripts/shorts/scheme.py --spec specs/<id>.json --out work/<id>/scheme_check --t <tl…>` → `B_<t>.png` (ещё `--t-offset`, `--id` при нескольких схемах).

```json
{"type": "scheme", "id": "whoiswho", "start": 306.6, "end": 316.6,
 "style": {"accent": "#F8DE03", "bg": "#000000", "bottom": "#60260A", "grid": 108, "pan": 0.45},
 "nodes": [
  {"id": "alex", "icon": "avatar", "at": 306.7, "offset": [0, 0],
   "phrases": [{"words": [["мой", 306.75], ["коллега", 306.9]], "out": 307.55}, {"words": [["Алексей", 307.6], ["Завар", 307.8]]}]},
  {"id": "ayugram", "icon": "logos/ayugram.png", "at": 308.55, "pan_at": 308.1, "offset": [830, 900],
   "phrases": [{"words": [["создатель", 308.8], ["AyuGram", 309.0]], "out": 309.65},
               {"number": ["1 000 000", 310.7], "words": [["активных", 311.1], ["пользователей", 311.35]], "line3": [["ежемесячно", 312.0]]}]},
  {"id": "funpay", "icon": "logos/funpay.svg", "shape": "plate", "at": 312.72, "pan_at": 312.3, "offset": [-440, 960],
   "phrases": [{"words": [["более", 314.7], ["чем", 314.85], ["на", 315.0]], "number": ["50 000", 315.3], "line3": [["пользователей", 315.5]]}]}
 ]}
```
Поля узла: `at` — pop узла; `pan_at` — начало переезда к узлу; `offset` — сдвиг от предыдущего узла, px мира; `phrases[].words` — [слово, время]; `number` — жёлтая строка (до слов, если её время раньше; после — если слова раньше, как «более чем на / 50 000»); `line3` — третья строка; `out` — cut фразы.

### Рилсы (Instagram)
- Та же спека, сборка с флагом: `python -X utf8 scripts/shorts/build.py <id> --config config.json --reels`. Результат — `out/reels/<id>_<slug>.mp4`, копия `work/<id>/final_reels.mp4`.
- Отличие от шортса — только концовка (4 с вместо 2.5): «Напиши «СЛОВО» в комментариях / и я пришлю тебе / полный урок». Кодовое слово — `"code_word"` в спеке, иначе `reels_word` в config.json; нет ни того, ни другого → ошибка (задать на каждый ролик).
- `mute` — `[[tl_a, tl_b], …]`: тишина на интервале таймлайна без склейки (оговорка), слово выпадает из субтитров. Действует и для шортса, и для рилса.

### Тиктоки
- `python -X utf8 scripts/shorts/build.py <id> --config config.json --tiktok` → `out/tiktok/<id>_<slug>.mp4`, копия `work/<id>/final_tiktok.mp4`.
- Блок `"tiktok": {"ranges": [...]}` в спеке — свои диапазоны (тизер: хук + одна мысль, речь ≤ 12.5 с).
- Концовка 2.5 с: скрин превью с названием (`tiktok_thumbnail` в config.json, необязательно) + плашка «Полное видео на YouTube: <канал>» (`tiktok_channel` в config.json). Канал не задан → «ПОЛНОЕ ВИДЕО НА YOUTUBE» + «ИЩИ ПО НАЗВАНИЮ ↑» и предупреждение в выводе; имя канала не выдумывать.
