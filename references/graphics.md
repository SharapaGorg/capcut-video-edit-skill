# Графика (этапы 7–8): HTML → Playwright → MOV

Единственный разрешённый путь. Текст CapCut (materials.texts), PIL/numpy-рендеры, Remotion, геометрия «на глаз» по коэффициентам px/size — запрещены. Хочется другой инструмент → вопрос пользователю (Стоп), не своё решение.

## Пайплайн
1. Композиция = HTML-файл 1920×1080 с прозрачным фоном, стили `scripts/graphics/html/base.css` (шрифт Unbounded из `assets/Unbounded-var.ttf`, плашки) + `gfx.css` (классы `.plate .num .sq .tile .arrow .hrow .vcol .it .dim .card .wall .name`), иконки `icons.js` (`<i data-icon="...">`).
2. Анимация — `anim.js`: детерминированная, по времени. `window.seek(t)` расставляет стили всем элементам с `data-in`.
   - `data-in` — момент появления, с; `data-out` — начало выхода (необяз.).
   - `data-fx` — вход: `slide-left|slide-right|slide-up|slide-down|pop|cut|wipe-left|wipe-right|wipe-up|wipe-down|grow-x` (по умолчанию slide-up); `data-ofx` — выход (по умолчанию обратный вход).
   - `data-dur` (0.22), `data-odur` (0.25), `data-dist` (28 px). Ease-out cubic, жёсткий вход.
3. `scripts/graphics/gfx_build.py` — описание композиций (`comp(id, start, end, body)`) → HTML + `comps.json` (id, файл, начало/конец на таймлайне).
4. `scripts/graphics/render.py` читает `comps.json`: Playwright Chromium, покадровые прозрачные скриншоты (`seek(frame/fps)`) → ffmpeg `prores_ks -profile:v 4444 -pix_fmt yuva444p10le` → `.mov` с альфой.
5. `scripts/graphics/preview.py` — кадры поверх реального фона (кадр исходника по timeline_map) → png для проверки.
6. `scripts/graphics/apply_graphics.py` (идемпотентный) — MOV как видеоклипы на дорожку графики; `apply_sfx.py` — SFX под входы.
7. Проверка: ffprobe — альфа (yuva); кадр из середины каждой поверх видео — шрифт, цвета, кружок и область, о которой речь, не перекрыты.

## Процедура
- Предложение (таблица этапа 7/8) → **одна тестовая** (самая сложная) → png поверх реального фона + вставка в проект → **ок пользователя в CapCut** (обязателен, не решать самому) → пачка в фоне.
- Новая графика позже = новый `comp()` → preview → render → apply_graphics. SFX к ней — добавить отдельно.
- Звук внутри MOV не нужен; SFX — отдельной дорожкой. Белый шум «шуршание» не использовать.

## Стиль «Монолит»
- Прямоугольные чёрные блоки #0A0A0A, без скруглений, без прозрачности плашек.
- Капс Unbounded 800–900. Оранжевый #D46A40 — номера и ключевые слова. Белая плашка с чёрным текстом — второй уровень.
- Сплит: левая половина чёрная.
- В иллюстрациях как можно меньше текста и больше чистоты; не обязательно прямоугольники — разъединённые части, иконки.
- Плотная моушн-графика: зумы, окна, плашки — пользователь хочет насыщенный монтаж.

## 15 элементов
- Структура: 01 заставка главы (камера·сплит, 6–8 раз, 2–3 с); 02 навигатор главы (левый верх, всё время кроме заставок, «03/08 · Тема»); 03 итоги главы (сплит, конец главы, 3 пункта).
- Камера: 04 плашка имени (низ слева, первые 30 с и при возврате на камеру после длинного скринкаста); 05 тезис (стена справа, 3–5 с); 06 цифра (камера·сплит, когда звучит число); 07 термин (первое упоминание).
- Скринкаст: 08 выноска (рамка + подпись на кнопку/поле/ответ); 09 фокус (затемнить всё кроме блока, 2–4 с); 10 шаги («Шаг 2 из 4 · …»); 11 карточка промпта (промпт, который зритель повторит); 12 рамка камеры (низ справа, рамка + подпись над кружком).
- Сплит и служебные: 13 список/сравнение (левая половина сплита, 3–5 пунктов, было/стало); 14 совет/важно (везде, 4–6 с); 15 ссылка/призыв (первое упоминание сервиса и финал, «<сервис> · ссылка в описании»).

## Типовые ситуации
- Текст за спиной и крупные заголовки: слово за головой, слово-удар, вопрос зрителю (текст за спиной: дубль слоя камеры → «Удалить фон» → копия над графикой).
- Окошки: окно браузера, веер окон, уведомления, диалог с нейросетью, телефон с рилсом.
- Футажи: на весь экран, в окне, стена роликов, сплит «футаж и я», скриншот на подложке.
- Иллюстрации: схема A → B → C, фичи с иконками, процесс по шагам, пометка-стрелка на камере, цифра в сплите.
- Скринкаст: лупа, затемнение-фокус, клик, ускорение ×4, «вручную / автоматически».
- Служебное: оглавление, «перематывайте на…», частая ошибка, шторка-переход, финальный экран, ссылка, промокод.

## Правила размещения
- Стена светлая → всё на камере лежит на чёрной подложке.
- Зона для тезиса на камере: стена справа от головы, x 1250–1860, y 120–420 (проверить по кадру ролика: где голова).
- Оранжевый рядом с лицом — только текст/тонкая деталь на чёрном, большими заливками никогда; оранжевые плашки и рамки — на скринкаст и в нижнюю треть.
- Контраст: оранжевый на чёрном / чёрный на оранжевом ≈ 5.5:1; белый на оранжевом только крупно (≥ 24 px).
- Графика на скринкасте не заходит в правый нижний угол (кружок). Карточка на скринкасте: правый верх, x 1240–1860, не ниже y 680.
- Графику не класть туда, куда показываю курсором / о чём говорю. Статичный скринкаст можно закрыть сплошным блоком.

## Уровни звука
- SFX / звук вставок = голос −12 LU (−7 LU было «слишком громко»). Заставки глав — на 3 dB тише SFX зумов.
- Музыка = голос −13 LU (−18 LU на динамиках ноутбука «слишком тихо»).
- Значения в dB сообщать пользователю, он может поправить.
